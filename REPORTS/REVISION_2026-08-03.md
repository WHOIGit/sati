## Defects the tests don't catch

- [x] **1. `sati train` crashes under stock augmentation defaults — HIGH.**
  `resolver.py:183` ends with `RootConfig.model_validate(cfg.model_dump())`;
  `model_dump()` emits unset fields, so revalidation marks *every* field as
  explicitly set. `YoloAugmentConfig.explicit_train_kwargs()` (`root.py:166`)
  then returns all 11 augment keys as `None` → `TypeError: 'close_mosaic=None'
  is invalid`. Breaks **3 of 4 committed experiment configs**
  (`fullres_bbox`, `sam2dirty/start_zoom`, packaged `experiment/example`); only
  `fullres_bbox_yolo_aug_off` survives because it sets every augment explicitly.
  Violates model-training spec ("only explicit augmentations") and
  DESIGN-DOC-v1 §3.3 ("omitted = stock default").
  - Test gap: `test_ultralytics_backend_train_kwargs` uses a `FakeYolo` that
    accepts any kwargs and never asserts omitted augments are absent.
  - Broader hazard: `model_fields_set` is unreliable anywhere downstream of
    resolution's dump→revalidate round-trip.
  - **Response (2026-08-03):** FIXED, then SUPERSEDED by the design change in
    #15. Initial fix: `explicit_train_kwargs()` (`root.py`) filters by value —
    skips any augment whose value is `None`, ignoring the unreliable
    `model_fields_set`. This alone stops the crash. #15 then made augmentation
    off-by-default so the numeric knobs are never `None` in the first place; the
    skip-`None` filter remains as the escape hatch for a per-knob `null` and for
    `auto_augment`. Verified: full suite 112 passed / 2 skipped, ruff clean,
    real CPU `sati train` completes on stock defaults.

- [x] **2. `main()` error path dumps a traceback, exits 1 not 2 — MEDIUM.**
  `cli.py:359-364` catches `LifecycleError`, prints the clean message, then
  raises `typer.Exit(2)` *outside* the Click context, so it escapes uncaught.
  Confirmed on collision refusal: correct message, then a full traceback, exit
  code 1.
  - **Response (2026-08-03):** FIXED. `main()` now raises `SystemExit(2)`
    instead of `typer.Exit(2)` — `typer.Exit` is a Click-internal signal only
    handled inside `app()`; `SystemExit` is what the interpreter turns into a
    clean exit code. Regression test added (`test_cli.py`:
    `test_lifecycle_error_exits_cleanly_with_code_2`) — the existing `CliRunner`
    tests invoke `app` directly and can't reach the `main()` wrapper. Verified:
    real collision refusal now exits 2 with the message and zero traceback
    lines; full suite 114 passed / 2 skipped, ruff clean.
    - Related (2026-08-03, Sidney requested): broadened to all user-facing SATI
      refusals. Added dep-free `src/sati/errors.py` with base `SatiError`;
      `LifecycleError`, `IngestError`, `TrainRefusedError`, and
      `ConfigCompositionError` now subclass it, and `main()` catches the base.
      Chose a shared base over importing the three classes into `cli.py` because
      `IngestError`/`TrainRefusedError` live in cv2-importing modules — a tuple
      import would drag `cv2` into every CLI startup (verified `cv2` stays out).
      All three verified: exit 2, clean message, 0 traceback lines. Parametrized
      regression test covers all four + a base-class guard. Suite 118 pass / 2
      skip, ruff clean.

    train/eval/infer/export runs — recorded paths resolve and the export
    `model_hash` matches the on-disk bytes. Regression test added

- [x] **4. `inspect config-compare`'s `other` isn't a residual — MEDIUM.**
  `inspect.py:116` builds `used` from hash-source diff keys, but
  `config_hash_source` nests under `"config"` and

## Code vs. Documented Design

- [x] **6. Path exclusion is a hand-maintained list.** Contradicts
  DESIGN-DOC-v1 §4.7's explicit *"Decided (2026-07-02): path exclusion is
  type-driven, never a hand-maintained list."* `hashing.py:168` hard-codes
  `("uri","split_file","image_root")` + `prepared["uri"]`. Currently equivalent
  to the type-driven set, but silently wrong the moment a path field is added
  under `model`/`training`/`slicing`. The guard test checks `bare_path_fields`
  only, not sentinelization coverage.
  - **Response (2026-08-03):** DONE via openspec `align-dojo-hash-mechanics`
    (applied). `hashing.py` now walks `SatiPathMarker` + `HashDerivedMarker`
    (`_EXCLUDED_SOURCE_PATHS`) and pops those fields from every source — no
    hand-listed keys. Guard test `test_generated_identities_are_hash_derived`.

- [x] **7. `HASH_DERIVED` is inert.** Declared, exported, and documented as
  "excluded from behavioral config hashes" — but never consumed.
  `annotated_field_paths` is only ever called with
  `SatiPathMarker`/`ResolvedOnlyMarker`. In practice
  `data.prepared.{dataset_hash,prepared_dataset_hash,prepared_dataset_id}` are
  HASH_DERIVED yet *are* in `config_hash`; `runtime.*` is excluded only by a
  hard-coded pop list (`hashing.py:161`).
  - **Response (2026-08-03):** DONE via openspec `align-dojo-hash-mechanics`
    (applied). `HASH_DERIVED` now drives `config_hash` exclusion, making it
    dataset-independent (verified: config_hash equal with/without dataset
    identities, where it previously differed).

- [x] **8. `task.kind` vs `task.type`.** DESIGN-DOC-v1:131 says `task.kind |
  detection`; code is `task.type: object_detection`. That table claims to be
  "the entire v1 option set" but omits `task.box_format`, `task.box_bounds`,
  `task.origin`, `data.source.dataset_id`, `model.num_classes`, `model.imgsz`.
  - **Response (2026-08-03):** FIXED (doc-only). Confirmed dojo uses `task.type`
    (a `Literal`) and `type` for every discriminator — SATI's code already
    matches the sibling, so the DESIGN-DOC table was the wrong artifact. Rewrote
    the §3.3 row to `task.*` = `type=object_detection` + the fixed
    `xyxy`/`half_open`/`top_left` coordinate literals; extended `data.source.*`
    to note optional `dataset_id`; added `model.num_classes` and `model.imgsz`
    rows so the "entire v1 option set" table is truthful. Grepped repo/docs — no
    other stale `task.kind`/`detection` references. No code change.
    - Follow-up (2026-08-03): investigated whether `task.box_format`/`box_bounds`/
      `origin` (single-value Literals, read by no code) have latent value for
      varied input bbox schemas (COCO/YOLO/VOC/LabelStudio). Conclusion: no —
      input variety is absorbed by adapters keyed on `data.source.format`;
      `task.*` describes the invariant internal target, and a richer *input*
      convention would belong under `data.source`. Folded a BREAKING
      simplification into openspec `align-dojo-hash-mechanics` (D7 / task 2.4):
      collapse `TaskConfig` to `type` only, move the coordinate convention into
      `target_schema_hash` as a versioned constant. When that change lands, the
      §3.3 `task.*` row updates to `type` only.

- [x] **9. `inspect config` ingests the entire raw dataset.** For train/eval
  with `data.prepared.uri` unset, resolution calls
  `populate_source_identities`. Write-free (spec-compliant), but read-only
  inspection now requires the raw dataset present — `sati inspect config
  experiment=v1/manual/fullres_bbox` fails with `IngestError: data.image_root
  is not a directory: /home/sbatchelder/…`. Worth a decision on graceful
  degradation.
  - **Response (2026-08-03):** DEFERRED into openspec `align-dojo-hash-mechanics`
    (D8 / task 3.4), sequenced after the `HASH_DERIVED` exclusion (#7 / D6).
    Chose Option A (dataset-free inspection, dojo-aligned) over a
    graceful-degradation stopgap. Rationale: `config_hash` currently *depends* on
    dataset ingest (verified — the two differ), so a dataset-free inspect is only
    correct once `HASH_DERIVED` excludes dataset identities from `config_hash`;
    hence it must ride with the hash change, not ship standalone. dojo already
    treats config inspection as dataset-free ("compare does not read datasets").
    DONE (applied): a `for_inspection` resolution mode skips ingest + the
    dependent prepare-path derivation; `sati inspect config` (the exact
    `IngestError` case) now succeeds with the dataset absent and previews the
    real run's `config_hash`.

## New design changes (this session)

- [x] **15. Augmentation off by default (spec change) — DONE 2026-08-03.**
  Chosen over #1's original "inherit Ultralytics defaults" contract. SATI now
  deactivates all YOLO train augmentation by default; Ultralytics' stock
  behavior is an explicit opt-in.
  - **Schema** (`root.py` `YoloAugmentConfig`): field defaults flipped from
    `None` to off-values (numerics `0.0`/`0`). `auto_augment` stays `None`
    (classification-only in Ultralytics — verified via `classify_augmentations`;
    a detection no-op). Per-knob `null` still defers that one knob to Ultralytics
    via the skip-`None` filter.
  - **New group** `src/sati/config_defaults/augmentation/`: `default.yaml`
    (all off; mirrors schema; intended `sati init` template) and
    `ultralytics.yaml` (stock 8.4.102 values). Opt in from an experiment with
    `- /augmentation@training.yolo_augment: ultralytics`.
  - **Experiments**: `fullres_bbox_yolo_aug_off` simplified to just its two flip
    overrides (rest inherited off). `fullres_bbox` and `sam2dirty/start_zoom`
    are UNCHANGED and therefore now train with augmentation OFF (previously
    implicit Ultralytics stock). **OPEN QUESTION — see below.**
  - **Docs/spec**: DESIGN-DOC-v1 §3.3 row + §8 decision rewritten;
    model-training openspec spec updated (off-by-default requirement + two new
    scenarios). `openspec validate --all --strict` = 8/8.
  - **Verified**: full suite 112 passed / 2 skipped, ruff clean, real CPU trains
    for both the off default and the `ultralytics` opt-in; Ultralytics trainer
    log confirms all knobs `0.0`/`0` on the default run.
  - **RESOLVED 2026-08-03 (Sidney):** leave `fullres_bbox` and
    `sam2dirty/start_zoom` OFF. No augmentation opt-in added; both now train
    with augmentation deactivated by design.
